# TaskFlow 用户流程与权限

## 1. 页面与导航

| 路由                                 | 页面               | 访问条件 | 主要操作                               |
| ------------------------------------ | ------------------ | -------- | -------------------------------------- |
| `/login`                             | 登录               | 仅访客   | 登录、跳转注册                         |
| `/register`                          | 注册               | 仅访客   | 注册、跳转登录                         |
| `/dashboard`                         | 看板               | 已登录   | 查看统计、进入最近项目                 |
| `/projects`                          | 项目列表           | 已登录   | 搜索、筛选、分页、新建项目             |
| `/projects/:projectId`               | 项目详情与任务列表 | 项目成员 | 编辑项目、管理成员、筛选任务、创建任务 |
| `/projects/:projectId/tasks/:taskId` | 任务详情           | 项目成员 | 编辑任务、评论、上传和下载附件         |

应用布局固定包含左侧主导航、顶部当前用户菜单和内容区。项目详情使用项目内局部导航，不另建独立顶部层级。

## 2. 核心流程

### 2.1 注册

1. 访客在 `/register` 输入用户名、邮箱和密码。
2. 前端执行必填、长度和格式校验。
3. 提交成功后建立登录状态并进入 `/dashboard`。
4. 用户名或邮箱冲突时留在注册页，保留非敏感输入并展示服务端消息。

### 2.2 登录与恢复

1. 访客在 `/login` 输入邮箱和密码。
2. 登录成功后保存 Token 和用户信息。
3. 刷新页面时，应用使用 Token 请求 `/auth/me` 恢复用户。
4. Token 缺失、过期或无效时清除本地状态并跳转 `/login`。
5. 退出登录仅清除本地 Token 和用户状态，不调用服务端退出接口。

### 2.3 创建项目

1. 用户在项目列表点击“新建项目”。
2. 输入项目名称和描述。
3. 服务端在事务中创建项目并写入当前用户的 `OWNER` 成员关系。
4. 成功后刷新项目列表，并允许进入项目详情。

### 2.4 管理成员

1. `OWNER` 在项目详情输入邮箱或用户名。
2. 服务端查找已注册用户并验证其尚未加入项目。
3. 添加成功后刷新成员列表。
4. `OWNER` 可以移除 `MEMBER`。
5. 用户不存在、重复添加或尝试移除 `OWNER` 时展示明确错误。

### 2.5 管理任务

1. 项目成员在项目详情选择“新建任务”。
2. 填写标题、描述、状态、优先级、负责人和截止日期。
3. 提交后刷新任务列表并展示成功反馈。
4. 成员可以编辑任务，且负责人必须属于当前项目。
5. 普通成员只能删除自己创建的任务；`OWNER` 可以删除任意任务。

### 2.6 筛选任务

1. 用户输入关键字或选择状态、优先级、负责人、截止日期。
2. 前端删除空筛选项，保留分页参数。
3. 服务端返回匹配项、当前页、每页数量和总数。
4. 筛选变化时将页码恢复为第 1 页。
5. 无匹配结果时展示空状态，不展示错误。

### 2.7 评论

1. 项目成员在任务详情输入 1 到 2000 个字符。
2. 发布成功后清空输入并刷新评论列表。
3. 评论作者或项目 `OWNER` 可以删除评论。
4. 删除前需要用户确认，删除成功后刷新列表。

### 2.8 附件

1. 项目成员选择 `.pdf`、`.png`、`.jpg`、`.jpeg` 或 `.txt` 文件。
2. 前端先检查文件大小不超过 5 MB。
3. 服务端再次检查类型、大小和任务附件数量。
4. 上传成功后刷新任务详情。
5. 下载由带鉴权的 API 返回，不暴露公开静态地址。
6. 上传者、任务创建人和项目 `OWNER` 可以删除附件。

### 2.9 删除项目

1. `OWNER` 选择删除项目并二次确认。
2. 服务端在一个事务中删除项目及关联成员、任务、评论和附件记录。
3. 数据库事务成功后尽力删除附件文件。
4. 文件清理失败不回滚事务，但记录日志。
5. 前端删除成功后跳转项目列表。

## 4. 授权实现要求

- 所有受保护 API 先执行 JWT 认证。
- 项目范围接口必须验证当前用户是项目成员。
- 仅 `OWNER` 执行的接口必须再次验证角色。
- 任务负责人必须是当前项目成员，创建和更新时都校验。
- 前端权限只控制展示和交互，不能替代服务端授权。
- 资源不存在与无权访问使用不同业务码；涉及敏感数据时允许服务端按统一安全策略返回 `PROJECT_MEMBER_REQUIRED`。

## 5. 页面状态

### 5.1 加载态

- 首次加载使用骨架屏或居中加载状态。
- 刷新列表时保留现有内容并显示局部加载。
- 提交按钮在执行期间禁用并显示加载状态，防止重复提交。

### 5.2 空状态

- 项目列表为空：提示尚无项目，提供“新建项目”。
- 任务列表为空：区分“项目尚无任务”和“筛选无结果”。
- 评论为空：提示尚未评论，并保留输入框。
- 附件为空：提示尚未上传，并提供上传入口。

### 5.3 错误态

- 页面级请求失败：显示错误说明和“重试”按钮。
- 表单校验失败：在字段附近展示具体原因。
- 业务错误：使用服务端中文消息，不暴露堆栈。
- `401`：清除本地会话并跳转登录页。
- `403`：留在当前页，说明缺少权限。
- `404`：显示资源不存在，提供返回上级页面操作。

### 5.4 操作反馈

- 创建、编辑、删除、上传和评论成功后使用消息提示。
- 删除项目、删除任务和移除成员需要二次确认。
- 列表操作成功后重新请求服务端数据，不只修改单个本地条目。

## 6. 响应式要求

- 1440 x 900：侧边栏展开，表格和筛选器完整显示，不发生横向重叠。
- 1920 x 1080：主内容最大宽度受控，统计卡片按网格扩展，不出现异常留白。
- 低于 1024 px：允许侧边栏收起、表格局部横向滚动，但核心操作仍可到达。
