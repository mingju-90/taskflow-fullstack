# TaskFlow 验收与测试矩阵

## 1. 验收层级

| 层级 | 工具 | 目标 | 执行时机 |
| --- | --- | --- | --- |
| 静态检查 | TypeScript、Vue TSC | 类型、导入和构建配置正确 | 每次提交、CI |
| 后端集成测试 | Vitest、Supertest、临时 SQLite | 验证 HTTP、Service、Prisma、权限和文件规则 | 每次提交、CI |
| 前端单元测试 | Vitest、Vue Test Utils | 验证 Store、Axios、权限、查询转换和关键表单 | 每次提交、CI |
| 端到端冒烟测试 | Playwright、Chromium | 验证真实浏览器和真实前后端核心链路 | CI、合并前 |
| 手工视觉验收 | 浏览器、截图 | 验证桌面尺寸、信息层级、状态和可访问性 | 原型评审、UI 完成后 |

## 2. 测试命名

- 后端测试：`server/tests/<domain>.test.ts`
- 前端测试：`client/tests/<domain>.test.ts`
- 端到端测试：`client/e2e/<flow>.spec.ts`
- 测试名称使用“行为 + 预期结果”，避免只写“works”。

## 4. 后端必测场景

- 注册、重复邮箱、重复用户名、登录、错误密码和当前用户。
- 缺少、格式错误、过期和签名错误的 Token。
- 项目创建与 `OWNER` 成员关系的事务性。
- 非成员访问项目、任务、评论和附件。
- `MEMBER` 尝试管理项目或成员。
- 负责人必须是项目成员。
- 任务筛选组合、分页边界和非法枚举值。
- 评论作者、任务创建人和 `OWNER` 的删除规则。
- 附件大小、MIME、数量、随机存储名和受控下载。
- 删除项目或任务后的关联记录和文件清理策略。
- 成功和失败响应都包含 `requestId`。

## 5. 前端必测场景

- Axios 自动添加 Bearer Token。
- 成功响应自动解包 `data`。
- 业务错误转换为带 `code`、`message`、`status`、`details`、`requestId` 的 `ApiError`。
- 认证 Store 的登录、注册、恢复和退出。
- 路由守卫在无 Token、有 Token、Token 失效时的行为。
- `canManageProject()` 等权限工具。
- `toTaskQuery()` 删除空值并保留分页参数。
- 关键表单的空值校验、最大长度和提交禁用。
- 删除确认取消时不调用 API。

## 6. 端到端冒烟流程

单一 Chromium 流程必须覆盖：

1. 打开注册页并注册新用户。
2. 进入看板并创建项目。
3. 进入项目并创建任务。
4. 修改任务状态为进行中或已完成。
5. 打开任务详情并添加评论。
6. 刷新页面确认数据和登录状态恢复。
7. 退出登录并确认回到登录页。

测试必须使用可访问名称定位，例如：

```text
用户名
邮箱
密码
注册
项目名称
保存
任务标题
新建任务
评论内容
发布评论
退出登录
```

## 7. 持续集成门禁

每次 `push` 和 `pull_request` 运行：

1. 安装 `server` 依赖并生成 Prisma Client。
2. 运行后端类型检查、集成测试和构建。
3. 安装 `client` 依赖。
4. 运行前端类型检查、单元测试和构建。
5. 安装 Playwright Chromium。
6. 运行端到端冒烟测试。
7. 任何步骤失败时整个工作流失败。

快速静态检查可以并行执行，端到端测试依赖前后端构建通过。CI 使用 Node.js 20，锁定依赖使用 `npm ci`。

## 8. 发布门禁

第一版只有满足以下条件才可标记完成：

- 设计、需求、接口和实施计划之间没有未解释冲突。
- 后端测试、前端测试、类型检查和构建通过。
- Playwright 冒烟流程通过。
- 在 1440 x 900 和 1920 x 1080 下检查核心页面无重叠和不可达操作。
- README 能在全新环境按步骤启动。
- 已确认不存在明文密码、公开上传目录或把前端权限当作后端授权的问题。

## 9. 手工视觉清单

- 登录和注册页面在两种桌面尺寸下表单宽度稳定。
- 看板统计卡片的数字、标签和进度条不溢出。
- 项目列表表头、筛选器、分页和操作按钮对齐。
- 项目详情的成员管理和任务列表层级清晰。
- 任务表单的字段、日期选择器和错误消息不重叠。
- 评论和附件区域在长内容下仍可阅读。
- 加载、空状态、错误、确认框和消息提示都有明确反馈。
